# OctoAcme Project Management Process Documentation

Welcome to the OctoAcme project management documentation. This folder brings together the core guidance, templates, and operating rhythms used to plan, deliver, and improve projects across the organization.

## Overview

OctoAcme’s project management approach is built around a simple, repeatable lifecycle: initiate work, plan delivery, execute in small increments, release with control, and reflect to improve the next cycle. The methodology emphasizes customer value, clear ownership, measurable outcomes, and iterative learning. Across all stages, the team is expected to align on goals, define responsibilities, communicate early and often, and maintain quality through testing, review, and evidence-based decisions.

The project management model is grounded in five core principles:
- Customer-first: prioritize customer value and usability.
- Iterative delivery: deliver small, testable increments.
- Clear ownership: give every project a named PM and Product Lead with clear responsibilities.
- Data-informed decisions: measure impact and iterate based on evidence.
- Psychological safety: encourage feedback, learning, and candid communication.

## Project Management Process Summary

OctoAcme starts each initiative with a structured initiation phase to validate the business need, confirm stakeholders, define success metrics, and decide whether to proceed with planning. Once approved, the team moves into planning, where the backlog is prioritized, scope is estimated, dependencies are identified, and release milestones are mapped. During execution, the delivery team tracks work using project boards, daily standups, and regular reviews while keeping progress, blockers, and risks visible. Releases follow a controlled checklist so that features are validated, communicated, and rolled back if needed. At the end of each sprint or major milestone, the team conducts a retrospective to capture lessons learned and convert them into concrete improvement actions.

## How to Use These Docs with Copilot Spaces

These process documents are designed to be used as structured context for Copilot Spaces, giving AI assistants a clear understanding of the organization’s project management standards. When a team adds this folder as repository context, Copilot can help with project setup, milestone planning, stakeholder communications, risk review, retrospective facilitation, and process adherence. This makes the docs more than static references—they become a reusable source of institutional knowledge for onboarding, execution support, and decision-making.

To get the most value from the docs in a Copilot Space:
- Keep the project charter and key project artifacts in the repository
- Add relevant process docs to the Copilot Space context when the project is in a specific lifecycle phase
- Use the roles and document summaries to frame role-specific guidance and team scenarios
- Revisit the docs during planning, execution, release, and improvement cycles to ensure consistency
